# Requer Python 3.10-3.12 para a pilha completa (a CI usa 3.11).
# Em 3.9 este conjunto NAO funciona: mediapipe 0.10.13+ e tensorflow 2.16+
# instalam (existe wheel cp39) mas quebram no import com
# "TypeError: unhashable type: 'list'". Foi testado -- nao e suposicao.
#
# Os tetos de versao abaixo existem porque as quatro bibliotecas principais
# brigam por causa do protobuf. Sem eles, uma instalacao limpa resolve pra uma
# combinacao que nao roda. O que cada um evita:
#
#   mediapipe <0.10.22  -> 0.10.35 e 1.0.0 nao declaram versao de protobuf, e o
#                          1.0.0 e outra API (major novo). A faixa 0.10.14-21
#                          declara protobuf>=4.25.3,<5, que e o que amarra o
#                          conjunto.
#   tensorflow <2.20    -> o 2.20 exige protobuf>=5.28, que conflita
#                          diretamente com o mediapipe acima. 2.16-2.19 aceitam
#                          protobuf 4.x.
#   onnx <1.17          -> onnx 1.19 (puxado por skl2onnx recente) exige
#                          protobuf>=5 e quebra o mediapipe com
#                          "MessageFactory object has no attribute
#                          GetPrototype" na criacao de qualquer detector.
#   opencv-python <5    -> o 5.0 e major novo e exige numpy>=2; nada aqui foi
#                          testado com ele.
#
# De proposito NAO fixamos a versao do protobuf: ela e consequencia dos tetos
# acima. Fixar um numero aqui foi tentado e deixou o arquivo impossivel de
# resolver, porque cada versao do mediapipe quer uma faixa diferente.
#
# Combinacao que resolve sem conflito (verificada em venv limpo):
#   mediapipe 0.10.21 | protobuf 4.25.9 | tensorflow 2.19.1 | onnx 1.16.2
opencv-python>=4.8.0,<5
mediapipe>=0.10.13,<0.10.22
numpy>=1.24.0
scikit-learn>=1.3.0
websockets>=12.0
onnx>=1.15.0,<1.17
skl2onnx>=1.16.0,<1.18
# Roda o .onnx recem-exportado pra conferir que ele bate com o que o app
# espera (computer/treino/exportar_onnx.py: valida). Sem ele o treino avisa e segue
# sem validar, e o erro so aparece com o app ja instalado no celular.
# Sem teto: ao contrario dos de cima, o onnxruntime declara 'protobuf' sem
# faixa nenhuma, entao nao participa da briga de protobuf descrita acima.
onnxruntime>=1.16.0
# Treino do modelo de gestos corporais (computer/treino/treinar_corpo.py) e
# app.py/modular ja importavam tensorflow sem ele estar pinado aqui.
tensorflow>=2.16.0,<2.20; python_version < "3.13"
# Preview de webcam em computer/treino/gravar.py.
Pillow>=10.0.0
